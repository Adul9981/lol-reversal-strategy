# 常见错误与禁止事项

> 每次犯同类错误之前必须先看这个文档

---

## ❌ 错误1：把「系列赛市场」当成「小局市场」分析

**错误做法**：分析 LoL: T1 vs Gen.G (BO3) 这种系列赛整体市场，认为它能代表每小局的赔率反转。

**正确认知**：
- 系列赛市场 = 谁赢得整个 BO3/BO5，价格历史跨越整个系列赛（2-5小时）
- **小局市场** = Polymarket 上单独的 **Game 1 Winner / Game 2 Winner / Game 3 Winner** 市场，每个只覆盖那一局比赛（约30-45分钟）
- 这两类是完全不同的市场，有各自独立的 market ID 和 token ID

**用户想要的是**：Game N Winner 市场的分析，即单局比赛中赔率从高跌低再反转的情况。

**如何找到小局市场**：
- 同一个 Polymarket event 下有多个 markets（子市场）
- 系列赛 market 的 outcome 是队名（T1 / Gen.G）
- 小局 market 的 question 是 "Game 1 Winner"、"Game 2 Winner" 等
- 需要在 Polymarket `/markets` API 中找到同一 event 下的所有子市场，筛选出 Game N Winner 类型

---

## ❌ 错误2：用结果反推「弱势方」

**错误做法**：用 `last_price_0` 判断谁赢了，再把赢的一方标记为「强势方」，推导出开局赔率。

**正确认知**：
- 「弱势方」应由**比赛开始时的第一个价格数据点**决定（第一个 price history 数据点）
- 开局赔率 < 50% 的那方 = 赛前弱势方
- 与最终谁赢无关

---

## ❌ 错误3：忘记过滤垃圾市场

每次处理数据前必须过滤掉：
- `outcome_0 / outcome_1` 为 `"Yes"` 或 `"No"` → Yes/No 胜负市场
- `outcome_0 / outcome_1` 为 `"Over"` 或 `"Under"` → 总局数大小盘
- `outcome_0 / outcome_1` 为纯数字 → 总局数预测市场

---

## ❌ 错误4：用首血时间来推断游戏开始时间

**错误做法**：假设首血发生在游戏开始后固定时间，用它来倒推游戏 00:00 时刻。

**正确认知**：
- 首血时间差异极大（1分钟 ～ 7分钟），不可用于推断游戏开始
- 正确方法：调用 LoL Esports livestats API，找到 `blueTeam.totalGold == 2500`（五人各500起始金币）且 `participants[x].creepScore == 0` 的帧 → 该帧的 `rfc460Timestamp` 即为游戏 00:00（精度 < 30秒）

---

## ❌ 错误5：假设「系列赛价格曲线可以切割成小局」

**错误做法**：试图从系列赛整体价格曲线中用波动率检测来推断 Game1/Game2/Game3 的时间边界。

**正确认知**：
- 小局市场本身就是独立的 Polymarket 市场，有自己的价格历史
- 直接获取 Game N Winner 市场的 token_id，调用 `/prices-history`，拿到的就是那一局的价格历史
- 无需从系列赛曲线中切割，也不需要波动率检测

---

## ❌ 错误6：Polymarket API 查询 limit 太小，漏掉市场

**错误做法**：用 `limit=50` 查询 Polymarket Gamma API，自认为已经找到全部活跃市场。

**症状**：
- 明明有市场（用户亲眼看到），查询却返回空 / 缺少结果
- 只找到 LPL 市场，漏掉同期活跃的 LCK 市场
- 用户反馈"你又犯了一个新错误"后才发现

**根因**：
- `tag_slug=league-of-legends` 下同一时段可能有 50+ 个 event（赛季级 + 对阵局 + Over/Under 盘）
- `limit=50` 时翻不到后面的对阵局市场
- 另外 LPL 比赛有时在 `esports` 标签下而非 `league-of-legends` 标签

**正确做法（已写入监控脚本）**：
```python
TAG_SLUGS = ["league-of-legends", "esports"]   # 两个标签都查
"limit": 100                                     # 最大值，不要用 50
```
- 两个 tag 各查一次，合并去重（用 event id 去重）
- limit 固定用 100（Gamma API 最大值）
- 查完后再用 EXCLUDE_KEYWORDS + Yes/No 过滤，确保不漏对阵局市场

## ❌ 错误7：EXCLUDE_KEYWORDS 过于激进，误杀了对战赛事

**错误做法**：将 `["playoff", "msi", ...]` 等关键词应用于所有事件标题，包括具体对战比赛。

**症状**：
- 用户能在 Poly 官网看到 KT vs DK、TOP vs WE 的比赛
- 监控脚本完全找不到这些市场
- 原因：`"KT Rolster vs Dplus KIA (BO5) - LCK Road to MSI"` 含 `msi` → 被过滤
- 原因：`"Top Esports vs Team WE (BO5) - LPL Playoffs"` 含 `playoff` → 被过滤

**根因**：
- EXCLUDE_KEYWORDS 设计初衷是过滤「赛季冠军」类长线市场（如 "LCK 2026 Season Winner"）
- 但联赛名中含 "msi"、赛段名中含 "playoff" 的**具体对战赛事**也被误伤

**正确做法（已更新 scripts/14_signal_monitor.py 和 15_watchdog.py）**：
```python
# 只对 不含 " vs " 的事件才用关键词过滤（赛季级/预测型市场都没有 vs）
if " vs " not in ev_title:
    if any(kw in ev_title for kw in EXCLUDE_KEYWORDS):
        continue
# 含 " vs " 的事件 = 具体对战，直接保留，不过滤
```

同时追加过滤 Odd/Even 盘（总局数奇偶）：
```python
outcome_set = set(o.lower() for o in outcomes)
if outcome_set in [{"yes", "no"}, {"over", "under"}, {"odd", "even"}]:
    continue
```

## 核心原则总结

| 我们要分析的 | 正确数据源 |
|------------|-----------|
| 每小局的赔率走势 | Game N Winner 市场的 price history |
| 游戏精确开始时间 | LoL livestats API（totalGold=2500帧）|
| 游戏精确结束时间 | LoL livestats API（gameState=finished 帧）|
| 系列赛整体走势 | 系列赛 Moneyline 市场的 price history（次要）|
