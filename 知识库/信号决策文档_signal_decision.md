## 一、系统整体架构

```
两层数据 → 两类信号 → 统一决策
                               
  实时层（LiveStats API）          价格层（Polymarket Gamma API）
  每 15 秒拉取                     每 90 秒刷新缓存
  ↓                               ↓
  战局信号                         价格信号
  （触发早，领先 Poly 5~15 分钟）    （延迟 5~15 分钟，但可自动化）
  ↓                               ↓
  └──────────── 统一决策引擎 ──────────────┘
                    ↓
              macOS 通知 / 下单指令
```

### 2.2 Polymarket 赔率数据（Gamma API）

| 字段 | 说明 |
|------|------|
| `outcomePrices` | JSON 字符串，解析后得 `[蓝方概率, 红方概率]`，如 `[0.35, 0.65]` |

## 三、信号类型

### 3.1 A 型信号 · 弱势方逆风

**含义**：强弱对阵中，弱队落后后赔率被压低，但战局数据显示仍有翻盘空间。

**触发来源**：LiveStats 战局数据（主要）+ Polymarket 赔率（参考显示）

**触发条件（全部满足）：**

```
硬过滤（任意一条不满足 → 直接跳过）：
  ① 游戏时间 ≥ 8 分钟        （避免开局噪音）
  ② 金差 < 3,000             （落后方落后 < 3000 金，1 次大龙约可补 2000 金）
  ③ 无抑制器被破             （inhibitors == 0，高地未被攻入）
  ④ 对方龙数 ≤ 2             （对方 3 条龙时下一条即龙魂，战力不成比例）

注意：Polymarket 赔率「不」作为触发条件，只作为参考信息。
       → 目的是在赔率移动「之前」发出通知，让用户抢先入场。
```

**信号强度分级（基于金差）：**

```
⭐⭐⭐ 极强  金差 < 1,000   （几乎持平，极可能是市场过度恐慌）
⭐⭐   强    金差 1,000–2,000
⭐    中    金差 2,000–3,000
```

**加分项（满足 ≥ 1 提高信心）：**
- 弱势方有「存活核心」：至少 1 名选手死亡 ≤ 1 次 且 参团次数 ≥ 3
- 即将到大龙/男爵刷新节点（20–25 分钟）
- 弱势方刚打赢一波小团战

**联赛优先级：**
- LCK 优先（历史翻盘率 24%，数据可靠）
- LEC 次之（21%）
- LPL 主观判断（20% 翻盘率，但存在非正常操作疑虑）
- LCS 跳过（14%，太低）

---

### 3.2 B 型信号 · 热门方临时低估

**含义**：大热门（开盘 ≥ 70%）因早期小失误被市场短暂低估，赔率临时下跌，这是噪音，应该买回。

**触发来源**：Polymarket 价格变动（需有上一次价格记录）

**触发条件：**

```
① 上次价格 ≥ 70%（是热门方）
② 本次价格在 58–82% 之间（仍在热门区间）
③ 跌幅 ≥ 8 个百分点（市场确实在过度反应）
```

**历史数据支撑（n=130场）：**

| 当前赔率区间 | 历史胜率 | EV |
|------------|---------|-----|
| 70–82%     | 96.7%   | +27.9% |
| 60–70%     | 81%     | 正 EV |
| 50–60%     | 70.6%   | 正 EV（减弱）|
| < 50%      | ⚠️ 不再是 B 型，不建议用此逻辑 | |

**联赛限制：LPL 不适用 B 型**（LPL 热门胜率仅 57.5%，接近随机）

---

### 3.3 系列赛胜者信号（独立市场）

**含义**：BO3/BO5 中，某队在 0-1 或 0-2 落后时，系列赛胜者市场会将其赔率压至极低（情绪折扣），但只要还有局数可打，折扣往往过度。

**特点：**
- 回撤大（可能从 10¢ 跌至 4¢），要求能接受中途 50-70% 浮亏
- 平均持仓周期：2-4 小时（整个系列赛）
- 与单局市场资金池独立（M2 规则）

## 四、完整决策逻辑流程

```
每 15 秒（LiveStats 轮询）：

1. getLive → 获取所有直播场次
2. 对每场比赛：
   a. window API → 拿最新帧
   b. 硬过滤检查：
      - 游戏时间 >= 8 min？
      - 无抑制器被破？
      - 金差 < 3000？
      - 对方龙数 <= 2？
   c. 全部通过 → 触发通知（附当前 Poly 参考赔率）
   d. 任意不满足 → 跳过

每 90 秒（Polymarket 缓存刷新）：
   - 拉取 league-of-legends + esports 两个 tag 下所有活跃市场
   - 模糊匹配当前直播队名 → 更新赔率缓存
   - 同时做 B 型检测：上次 vs 本次价格对比

通知内容包含：
   - 信号强度（⭐⭐⭐ / ⭐⭐ / ⭐）
   - 当前金差
   - 游戏时间
   - 当前 Poly 赔率 + 提示（⚡未更新 / 🔶部分更新 / 🔴已更新）
   - 龙数和塔数
```

## 五、仓位规则（M1 / M2）

> **核心原则**：入场前算总美元投入，不看份数。

### M1 · 单局市场仓位上限

| 联赛 | 信号类型 | 单笔上限 |
|------|---------|---------|
| LCK  | A 型（弱势方） | $30 |
| LCK  | B 型（热门方） | $150 |
| LPL  | 任何策略 | $30 |
| LEC  | A 型 | $20 |
| LEC  | B 型 | $50 |

### M2 · 系列赛市场仓位

- 与单局共用额度会导致「前面输多了，系列赛机会来了没钱买」
- 建议单独预留 LCK $50–100 作为系列赛专用额度

## 六、持仓管理

```
买入后：
  ① 价格从买入价涨至 3–5 倍 → 卖出 50%，剩余持有到结算
  ② 价格继续跌破买入价 20% → 观察，不加仓（可能是假底）
  ③ 买入后 30 分钟无任何回升迹象 → 接受亏损，不追仓

系列赛持仓：
  - 单局价格波动是噪音，不影响持仓决策
  - 看剩余局数和整体趋势，不看中途赔率
```
