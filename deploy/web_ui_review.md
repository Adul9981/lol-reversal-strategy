# Web UI 设计审查意见
# LoL Polymarket 自动交易系统

> 基于 `web_ui_spec.md` 和 `web_ui_design.md` 的审查，结合实盘交易经验。  
> 日期：2026-06-09  
> 共 7 条修改意见，其中 4 条为 MVP 必须修复。

---

## 🔴 MVP 必须修复（4条）

### ② 信号类型（A型 / B型）必须显示

**位置**：页面一赛程表「信号」列 + 页面二信号面板标题

**问题**：原设计只显示信号强度（⭐⭐⭐），未区分 A型 / B型。

**影响**：A型和B型对应完全不同的 M1 仓位上限：
- LCK A型：单笔 ≤ $30
- LCK B型：单笔 ≤ $150

用户不知道信号类型，手动模式下无法判断应用哪个额度上限，极易超仓。

**修改方案**：
- 赛程表信号列：`⭐⭐ A型` / `⭐⭐ B型`（加色块区分，A型紫色，B型绿色）
- 信号面板标题：`⭐⭐ A型信号触发 · 第19分钟`
- 交易记录表增加「信号类型」列

---

### ③ Polymarket 价格滞后状态标签

**位置**：页面二，双方赔率数字旁边

**问题**：原设计只显示赔率数字（如 `35¢`），用户无法判断这个价格是否已经反映了当前战局。

**影响**：我们系统的核心优势是「比 Polymarket 早 5~15 分钟发出信号」。如果 UI 上没有体现这个信息差，用户无法判断入场时机是否仍然有效。

**修改方案**：赔率数字后面加滞后状态标签：

| 标签 | 含义 | 颜色 |
|------|------|------|
| `⚡ Poly未更新` | Polymarket 价格仍然偏高，市场还没反应，最佳入场窗口 | 黄色 |
| `🔶 部分更新` | 赔率已开始移动，窗口收窄 | 橙色 |
| `🔴 已更新` | Polymarket 已消化，核实后再决定 | 红色 |

判断逻辑（后端计算后推给前端）：
- 落后方 Poly 价格 ≥ 45% → 未更新（市场还没压低）
- 落后方 Poly 价格 25–44% → 部分更新
- 落后方 Poly 价格 < 25% → 已更新

---

### ④ 自动模式下必须有平仓按钮

**位置**：页面二，区域C「信号与操作」面板

**问题**：原文档 MVP 范围（第8.1节）写明：自动模式信号面板「仅展示，不含操作按钮」。

**影响**：自动买入后如果局势突变（对方破抑制器、队伍全灭），需要立刻手动强制平仓。没有平仓按钮，用户只能眼看着仓位归零。

**修改方案**：自动模式面板内增加：

```
✅ 已自动买入：KT Rolster $30 @ 21¢
   当前估值 $30 → $41（+$11，+37%）

[ ⚠️ 一键平仓（当前 +$11）]   ← 新增，点击后弹出确认弹窗
```

- 对应后端接口 `POST /api/v1/orders/close` 已存在，只需前端接入
- 点击后弹出确认弹窗，显示当前价格和预计回收金额

---

### ⑤ 时间线记录「风控拒绝」事件

**位置**：页面二，区域D「本场事件记录」时间线

**问题**：原设计时间线只记录「信号触发」和「成交」两类事件。

**影响**：自动模式下，如果信号触发但因为额度用满被风控拒绝，用户完全不知道发生了什么——既看不到通知，也看不到记录。

**修改方案**：时间线新增一类事件「风控拒绝」：

```
第21分钟  ⚠️  风控拒绝：LCK A型额度已用满（$30/$30），信号跳过
```

- 显示颜色：黄色警告色
- 同时需要更新后端 `signal` WebSocket 事件，增加 `rejected: true` 和 `reject_reason` 字段

## 🟡 建议修改（3条）

### ① 顶栏增加数据健康指示灯

**位置**：所有页面，全局顶栏

**问题**：`sync_health` 字段只在 `GET /api/v1/health` 接口中存在，没有在任何页面 UI 上显示。

**影响**：LiveStats API 在局间会返回 HTTP 204，偶发超时。数据已经 30 秒没更新时用户毫无感知，可能基于过时数据做决策。

**修改方案**：顶栏右侧加一个小指示灯：

| 状态 | 显示 | 颜色 |
|------|------|------|
| `NORMAL` | `● 数据正常` | 绿色 |
| `STALE_LOL` | `⚠️ LiveStats 延迟 Xs` | 黄色 |
| `STALE_PM` | `⚠️ Polymarket 延迟` | 黄色 |
| `DESYNCED` | `❌ 数据中断` | 红色 |

数据来源：`health_status` WebSocket 事件（已在设计文档中定义）。

### ⑥ 交易记录增加「信号类型」列

**位置**：页面三，今日交易记录表

**问题**：交易记录缺少信号类型字段，无法事后分析哪类信号盈亏比更好。

**修改方案**：在「比赛」和「入场价」之间增加「信号类型」列：

| 时间 | 比赛 | **信号类型** | 入场 | 出场 | 金额 | 盈亏 |
|------|------|------------|------|------|------|------|
| 19:03 | KT vs DK G3 | **A型** | 21¢ | 持仓中 | $30 | +$11 |

- A型：紫色标签
- B型：绿色标签
- 系列赛：蓝色标签

---

### ⑦ 额度使用区域增加「系列赛专项（M2）」

**位置**：页面三，今日额度使用进度条区域

**问题**：原设计额度进度条只有 LCK/LPL/LEC 等联赛维度，没有系列赛市场的独立额度。

**背景**：系列赛胜者市场（BO3/BO5 的总冠军市场）与单局 Game Winner 市场是完全不同的市场类型，仓位逻辑不同，必须用独立额度（M2规则），否则：
- 前几局单局交易用完额度
- 系列赛最高 EV 机会来临时已无资金（KT #024 的教训）

**修改方案**：进度条列表末尾增加：

```
系列赛专项（M2）    $35 / $100    ████░░░░░░
```

- 颜色与其他进度条区分（用紫色）
- 系列赛市场下单时从此额度扣除，不影响单局额度
